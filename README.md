# Лабораторная работа №3 - Интеграционное тестирование

## Описание проекта

Проект реализует систему работы с треугольниками, включающую:
- Классификацию треугольников по типу
- Сохранение результатов в базу данных SQLite
- Взаимодействие с пользователем через консоль
- Отправку результатов стороннему сервису (имитация)

## Структура проекта

```
.
├── src/
│   ├── triangle.py          # Класс вычислений (классификация треугольников)
│   ├── database.py          # Класс работы с БД (SQLite)
│   ├── user_interface.py    # Класс взаимодействия с пользователем (ABC)
│   ├── external_service.py  # Класс сторонней зависимости (ABC)
│   └── controller.py        # Класс-контроллер (бизнес-логика)
└── tests/
    └── test_integration.py  # Интеграционные тесты
```

## Архитектура

### Классы

1. **Triangle** - класс вычислений/валидации (из Лабораторной №1)
2. **TriangleDatabase** - работа с базой данных SQLite (добавление, получение, удаление)
3. **IUserInterface / ConsoleUserInterface** - взаимодействие с пользователем (ABC интерфейс)
4. **IExternalService / EmailService** - имитация отправки данных (ABC интерфейс)
5. **TriangleController** - контроллер с бизнес-логикой

### Бизнес-логика (TriangleController.process)

1. Запрашивает у пользователя длины трёх сторон
2. Проверяет наличие записи в БД:
   - Если есть → берёт результат из БД
   - Если нет → вычисляет тип треугольника и сохраняет в БД
3. Отправляет результат стороннему сервису
4. Возвращает результат

## Запуск тестов

```bash
python -m unittest tests.test_integration
```

Или с подробным выводом:

```bash
python -m unittest tests.test_integration -v
```

## Тесты

Реализовано 5 тестов:
- **3 интеграционных теста**:
  1. `test_full_workflow_with_calculation` - полный сценарий с вычислением
  2. `test_full_workflow_from_database` - получение результата из БД
  3. `test_full_workflow_with_invalid_triangle` - обработка невалидного треугольника
  
- **2 дополнительных теста**:
  4. `test_console_user_interface_integration` - имитация реального ввода пользователя
  5. `test_database_operations_integration` - проверка операций БД

Все тесты используют:
- `unittest.mock` для создания заглушек (Mock)
- `patch` для имитации пользовательского ввода
- Временную БД SQLite для изоляции тестов

## Технологии

- Python 3.x
- unittest (встроенная библиотека)
- unittest.mock (тестовые заглушки)
- SQLite3 (встроенная библиотека)
